
# AE Domain Mapping Specification

## 1. Overview

The Adverse Events (AE) domain describes adverse events
reported for clinical trial participants.

This module transforms synthetic raw adverse event records
into a standardized subset of CDISC SDTM AE variables.

The implementation is intended for educational and
demonstration purposes and does not establish full CDISC
SDTM compliance.

## 2. Input Datasets

### Raw Adverse Events

Source: `inst/extdata/raw_ae.csv`

Granularity: One record per reported adverse event.

Required variables:

- subject_id
- site_id
- event_id
- event_term
- severity
- serious
- relationship
- outcome
- start_date
- end_date

### Demographics Reference

Source: DM dataset generated by `generate_dm()`.

Required reference variables:

- STUDYID
- USUBJID
- SUBJID
- SITEID
- RFSTDTC

Granularity: One record per study participant.

## 3. Target Dataset

Domain: AE

Granularity: One record per adverse event.

Primary key:

STUDYID + USUBJID + AESEQ

## 4. Variable Mapping

| Target | Source | Derivation / Mapping |
|---|---|---|
| STUDYID | DM.STUDYID | Inherited from DM |
| DOMAIN | Constant | AE |
| USUBJID | DM.USUBJID | Matched using subject_id and site_id |
| AESEQ | Derived | Sequential integer within each subject |
| AETERM | event_term | Reported adverse event term |
| AEDECOD | Synthetic dictionary | Demonstration standardized term |
| AESEV | severity | Map to MILD, MODERATE, SEVERE |
| AESER | serious | Map Yes/No to Y/N |
| AEREL | relationship | Map to study-specific categories |
| AEOUT | outcome | Map to standardized outcome values |
| AESTDTC | start_date | ISO 8601 calendar date |
| AEENDTC | end_date | ISO 8601 calendar date or missing |
| AESTDY | Derived | Start study day relative to RFSTDTC |
| AEENDY | Derived | End study day relative to RFSTDTC |

## 5. Controlled Value Mappings

### Severity

| Raw | Target |
|---|---|
| Mild | MILD |
| Moderate | MODERATE |
| Severe | SEVERE |

### Seriousness

| Raw | Target |
|---|---|
| Yes | Y |
| No | N |

### Relationship

| Raw | Target |
|---|---|
| Related | RELATED |
| Not Related | NOT RELATED |

Relationship categories are study-specific demonstration
values.

### Outcome

| Raw | Target |
|---|---|
| Recovered | RECOVERED/RESOLVED |
| Recovering | RECOVERING/RESOLVING |
| Not Recovered | NOT RECOVERED/NOT RESOLVED |

## 6. Synthetic Coding Dictionary

| Reported Term | Demonstration Standardized Term |
|---|---|
| Headache | HEADACHE |
| Nausea | NAUSEA |
| Fatigue | FATIGUE |
| Abdominal pain | ABDOMINAL PAIN |
| Diarrhea | DIARRHOEA |
| Dizziness | DIZZINESS |
| Pneumonia | PNEUMONIA |

This dictionary is synthetic and is not a licensed MedDRA
dictionary. No official medical coding is performed.

Unmapped terms must trigger an explicit error.

## 7. Sequence Derivation

AESEQ is assigned within each STUDYID and USUBJID.

Records are sorted by:

1. AESTDTC
2. event_id

Sequence numbers start at 1 and increment by 1.

event_id must be unique within each subject.

## 8. Study Day Derivation

Study days are calculated relative to DM.RFSTDTC.

If event date >= RFSTDTC:

    Study Day = Event Date - RFSTDTC + 1

If event date < RFSTDTC:

    Study Day = Event Date - RFSTDTC

There is no Study Day 0.

If the event date or reference date is missing,
the derived study day is missing.

## 9. Validation Rules

- Required input columns must exist.
- Raw event identifiers must not be missing.
- Event identifiers must be unique within each subject.
- Every AE subject must exist in DM.
- The DM reference must contain unique subject keys.
- STUDYID and DOMAIN must be consistent.
- AESEQ must be a positive sequential integer.
- Target primary keys must be unique.
- Controlled values must follow the defined mappings.
- Dates must be valid YYYY-MM-DD calendar dates.
- Event end date must not precede event start date.
- Missing end dates are allowed.
- Study day values must not equal zero.
- Raw and output event counts must match.

## 10. Scope and Limitations

- Synthetic clinical trial data only.
- Selected AE variables, not a complete SDTM AE domain.
- Full calendar dates only; partial dates are not supported.
- A single study per pipeline execution.
- No official MedDRA coding.
- No regulatory submission validation.
- CSV export for the initial implementation.
